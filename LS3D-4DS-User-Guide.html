Mafia Toolkit — User Guide

Mafia’s models, animations, movement tracks and shadows, in Blender. This is the way in: it starts at installing and walks through a prop, a car and a character, in the order you meet them. The Field Manual beside it is the reference to look single things up in, and the README is the record of what changed and why.

Everything here is written against 1.0.2, on Blender 5.2 or newer.

01Installing

Install the zip through Edit › Preferences › Add-ons › Install from Disk, pick mafia-toolkit-1.0.2.zip, and switch it on. It asks for Blender 5.2 or newer.

The one setting to fill in

Texture Folder has to point at the game’s maps directory — the folder holding TOMMY1.BMP and its thousands of neighbours. A model names its textures by file name and nothing else, so without this an import comes in grey and says “No texture folder configured; textures will not be loaded”. Nothing else is broken by it: the model, its materials and every flag are read either way.

A Blender upgrade forgets it

A new Blender version starts a fresh configuration folder, so the add-on and this setting do not carry across. Install again and point the Texture Folder at maps again.

The two switches under it

  • Show Raw Flag Values puts the hexadecimal word beside each panel of switches. Useful when comparing a model against one the game ships; noise otherwise.
  • Show Engine-Reserved Flags reveals bits the engine keeps to itself. They are written back exactly as they came in whether this is on or off — it only decides whether you see them.

From a command prompt

The add-on can install itself, which is worth knowing on a machine that has nothing but Blender on it. The zip and the mbt.bat beside it are a whole working copy:

mbt --install --textures "D:\Hry\Mafia Editovani\maps"

That installs it into the newest Blender it finds, switches it on, keeps the texture folder and saves the preferences. Nothing else is needed — Blender brings its own Python. There is more on this in section 11.

02A tour

Five places hold everything the add-on does: two menu entries, one properties panel, three sidebar tabs, and what the viewport draws by itself.

File › Import and File › Export

Four formats, each with an entry under both menus:

FormatWhat it holds
.4dsThe model: every frame, its geometry, materials and hierarchy.
.5dsOne animation for that model, keyed by frame name.
.tckThe movement track beside an animation: where the actor travels while it plays.
.6dsThe coarse shadow mesh the engine casts from.

The import dialog has two options:

  • Collection Per Model puts everything the file holds in a collection named after it, so two models in one scene stay apart.
  • Load Its Animation looks for a .5ds named like the model beside it and loads that too.

The export dialog has five:

  • Selected Objects Only writes the selection instead of the scene. Every check and every message then talks about those objects only.
  • Fix >2 Joint Influences, Fix Non-Parent-Child Weights — weight corrections the game’s own rules need. See section 8.
  • Fix Long Rotation Turns splits a rotation that turns more than half a circle between two keys, which the game would otherwise play the short way round.
  • Write Its Animation writes a .5ds beside the model from the scene’s own actions.
  • Write Its Track writes the .tck holding where the actor travels while that animation plays, under the same name again. On by default, and available while the animation is being written and an empty in the scene carries movement. The travel is a file of its own that the game opens beside the animation, so without it a model that came in with a .tck goes back out standing still.

Where an animated object sits in the model

A .4ds holds one transform per frame, and an animation replaces it while it plays. So for an object an animation moves, the add-on has to decide which moment goes in the model, and there are two answers depending on how the object was set up.

  • Its Delta Transform holds a place — that is the model’s. This is what a model opened from a file has: the import puts the frame’s own transform there and leaves the location, rotation and scale free for the animation to key. New Animation sets it up the same way. Loading an animation onto such a model changes nothing the model writes, whatever frame the timeline is sitting on.
  • It holds nothing there — then the object is written standing exactly where the viewport shows it at the moment you press Export. An object you keyed yourself with the I key has its place in the very channels the animation keys, and there is nowhere else to read it from. The report names every object placed this way and the frame it took, so it is never a surprise.

The second case is the one to know about: move the timeline and the model you export changes with it. To pin a place instead, put it in the object’s Delta Transform (Object Properties › Transform › Delta Transform) and let the animation key the channels above it.

Parenting, and what a frame really holds

A frame holds the whole step from the frame above it, and in Blender that is more than an object’s own location, rotation and scale. Parenting with Ctrl+P keeps an object where it stands by storing the inverse of its parent’s place at that moment and multiplying it in underneath everything the object does afterwards; an object hung on a bone hangs from the bone’s end rather than its start. Both are part of the step, and both the model and the animation are written through the same one, so the two can never place a frame differently. Nothing here is anything you have to set — parent things however you like.

The 4DS Object panel

In the Properties editor, on the Object tab, under 4DS Object Properties. This is where an object says what it is: its Frame Type and, for a visual frame, its Visual Type, plus the panels of switches that belong to it. Typing 4DS in that editor’s search box hides everything else, which is the quickest way to see only this.

The three sidebar tabs

Press N in the 3D viewport:

  • 4DS Model — the scene as a whole: Check 4DS Scene, the animated object count, and everything to do with joints.
  • 4DS Morph — morph groups and their targets, for a mesh set to Morph or Single Morph.
  • 5DS Animation — the animation list, the frame rate, event cues and the movement track.

Add › 4DS

The Add menu builds the frames that are not ordinary meshes — a dummy, a sector, a portal, an occluder, a target, a light, a projector, a mirror, a billboard, a lens flare, a sun flare, a single joint, or a whole character skeleton. Each one comes out set up the way the game’s own models have it, and says in the status bar what to do next.

What the viewport draws

The add-on draws what the file describes but Blender shows nothing for: a dummy’s box and a mirror’s bound, the volume a projector covers, what a light reaches, each joint’s influence box, and the frame an armature stands on. Every box carries a dot at its middle, and a box that does not sit on what it belongs to is joined to it by a dashed line — the same way Blender draws its own relationship lines, and following the same overlay switch. Objects are colored by what they are: sectors and occluders as wireframes, portals in violet, skinned meshes in pink.

03Opening a model

Start with one the game ships. File › Import › 4DS Mafia Model, and pick something out of models — Tommy.4ds is a good first one, since it carries nearly everything the format has.

Reading the report

Every import and export writes a staged log to the system console (Window › Toggle System Console) and opens a summary when anything needs your attention. The log names each material and each frame as it goes, so a file that stops halfway says which item it stopped on:

==============================================================
[MBT/4DS] Importing Tommy.4ds
==============================================================
[MBT/4DS] Version 29, 5 material(s), 24 frame(s)
--- Materials ---
  [Mat 01/05] TOMMY1.BMP 0x00040001
--- Frames ---
  [Frame 01/24] 'base' Visual/Single Morph
  [Frame 02/24] 'r_thigh' Joint
--- Post-processing ---
  > Building armature (18 joint(s))
  > Applying skinning (1 mesh(es))
--- Viewport ---
[MBT/4DS] Import OK: Tommy.4ds

Lines are tagged [MBT/4DS], [MBT/5DS] and so on, so the add-on’s output can be picked out of a shared console.

What you are looking at

The model lands in a collection named after the file. Each object carries its frame type and, where it has one, its visual type — the panel in section 2 shows them. A character brings an armature with its joints, its skin weights and its morphs; a building brings its sectors and portals; a car brings its wheels and its dummies.

Export it straight back

A model imported and exported again comes back byte for byte, the save date aside. That is worth trying once on a file you care about: if it round-trips, everything the file held survived the trip into Blender, whether or not the add-on has a control for it.

04Checking a scene

This is the section to open when the export will not go through. Check 4DS Scene, at the top of the 4DS Model sidebar tab, runs every check the export runs and writes nothing. Press it before a long export, and after anything you are not sure about.

Errors stop the export. Nothing is written

The export builds the whole file in memory and checks it before a single byte is written, then writes to a temporary file and moves it into place. A failed export leaves whatever was there untouched — no half file, no leftover.

The refusals, and what each one means

Warnings let it through

A warning means the file was written and something in it is not what you might expect — a texture the folder does not hold, a character mesh not called base, a joint with no box written the default one, weights corrected to the two the game allows. Read them once; they say exactly what changed.

The console has the full story

The dialog shows the first dozen entries. Window › Toggle System Console has every one, in order, with the frame or material each belongs to.

05A prop, with LODs

The simplest thing worth exporting: one mesh, one material, and two coarser copies the game swaps in as you walk away from it.

1. The mesh

Model it, or bring one in. Then, in the 4DS Object panel, set:

  • Frame Type: Visual — it is something you can see.
  • Visual Type: Object — an ordinary mesh. Lit Object is the same thing with baked lighting the mission holds; Single Mesh is a skinned one; the rest are their own kinds, covered in section 10.

2. Its levels of detail

A LOD is a child of the mesh, named after it with _lod1, _lod2 and so on. The suffix is the whole rule: nothing else marks them.

Each LOD carries the distance it takes over at, in meters, in its own object panel. The first one is the mesh itself, at zero. Give the coarser ones the distance you want the swap to happen at — 10 m, 30 m — and remember the game measures from the camera.

One frame, several meshes

The model holds a LOD chain as a single frame carrying several meshes, so the whole chain comes out as one object in the file. Blender shows them as parent and children because that is the only way to hold several meshes in one place.

3. Its material

One material, its texture named by file name. Section 6 is the whole story; for a plain prop, a diffuse texture and nothing else is enough.

4. Write it

File › Export › 4DS Mafia Model. Read the report. Then drop the file into the game's models folder and look at it in game.

06Materials

A material is one flag word, some colors, an opacity and up to three textures. The panel is in the Properties editor on the Material tab, under 4DS Material Properties.

The three boxes

  • Diffuse — the texture the surface is painted with. Use Diffuse Texture has to be on for it to be read at all; a texture set with the switch off is a warning at export, because that is almost always a mistake.
  • Alpha — a second texture holding transparency, with Use Alpha Texture to switch it on.
  • Environment — a reflection texture, blended over the diffuse by the environment ratio.

Draws as

The panel says, in words, what the game will do with the combination you have set: opaque, blended at some opacity, cut out by a color key, added, and so on. It is worked out the way the engine works it out, so it is the quickest way to see whether the switches you picked mean what you wanted.

Color keys

A color-keyed material cuts away every pixel of one color — the game's usual way of making a fence, a sign or a railing. Switch on Color Key and the add-on reads the key color out of the texture's own palette when it is a paletted BMP, which is what the game's textures are. The preview in Blender cuts exactly what the game cuts.

Animated textures

A material can play a sequence of textures: FIRE00.BMP, FIRE01.BMP and on. Only the last two digits change, and the count and period live on the material. The panel says which files it expects and how many it found, and offers Fix Texture File where one of them is written in a way the game misreads.

Textures are named, not embedded

A model holds file names. Anything you use has to exist in the game's maps folder under that name, in a format the game reads — and the add-on warns at export about any that do not.

07A car

A vehicle is an ordinary model whose frames carry names the game looks for. Get a name or a frame type wrong and the car loads with that part missing and no message about it — this is the single most common reason a car comes out broken.

The frame type is what the game tests

Each lookup asks for a name and a kind. In Blender that kind is the Frame Type field in the 4DS Object panel, not what sort of Blender object it is. In practice an empty is a Dummy, with its box drawn from the empty's size, and a mesh is a Visual · Object. A name looked for as a dummy never finds a mesh, and the other way round.

The shape it makes

carname                  the model itself, named without the two-digit suffix
 |
 +- BODY                 dummy or mesh    everything is measured from it
 |   +- CENTRE           dummy            the collision box; no car without it
 |   +- BODYCOL0 ...     dummies          crash volumes
 |   +- BALLAST0 ...     dummies          weight points (only found under BODY)
 |   +- body panels      meshes           [DEFORM BODY] / [DEFORM GLASS] ...
 |
 +- DWHL0  DWHR0  ...    dummies          wheel mounts, UPPER CASE, one per wheel
 |   +- WHL0  WHR0       meshes           the wheels; the mount carries [15], the trail width
 +- AXISL0a ...          meshes           suspension arms, carrying [x y z] offsets in cm
 |
 +- DOOR1 ...            meshes           hinged panels; [DEFORM BODY,I] reverses the hinge
 |   +- WINDOW1          mesh             the glass that winds down (only found under its door)
 +- SEAT0                dummy            the driver; SEAT1 ... the passengers
 +- HEAD                 dummy            the driver's head

Three things worth knowing before you start

  • Case matters where the game says it does. The wheel mounts are DWHL and DWHR in upper case; several other names are matched without regard to case. The reference page gives the exact spelling each one needs.
  • Two names are searched in one place only. BALLAST* is looked for beneath BODY, and WINDOW* beneath its own door. Everything else may sit anywhere in the tree.
  • Text in a name does work. [DEFORM BODY], [15], [x y z] — square brackets on a frame carry numbers and switches the game reads. They are listed in the 4DS User Properties reference.

Every name, with what happens when it is wrong, is in LS3D-4DS-Dummy-Names.html beside this guide. Start from a car the game ships: import it, look at how its frames are named and typed, and build yours the same way.

08A character

Two things decide whether a character works at all

Its mesh has to be called base, and its armature has to stand where the game's animations expect — at hip height, held in the armature's Delta Transform. The game's own animations move the body through the frame of that name and only turn the joints. Get either wrong and the limbs bend while the body stays standing through a crouch or a roll, or the whole character floats.

1. The skeleton

Add › 4DS › Character Skeleton builds Tommy's: eighteen joints in the order the game numbers them, standing at the default mesh origin, with the character's usual extra frames — notify for animation cues, gun1 and gun2, blnd and targetN. Building one by hand works too: Add › 4DS › Joint adds a joint at the 3D cursor, on a new armature or on the one you have.

2. The mesh

Name it base. Set Frame Type: Visual and Visual Type: Single Mesh — or Single Morph if it has shape keys. Parent it to the armature and give it an Armature modifier pointing at the same armature. Its origin can be anywhere; what matters is the armature's.

If the armature is not standing where it should, press Set Default Mesh Origin in the 4DS Model tab. It works the place out from the character's own skeleton — 6.66 cm above the point midway between its l_thigh and r_thigh joints — so a character of another size stands at its own hip height, not Tommy's.

3. Weights, or boxes

The game plays vertex weights, and it plays them under two rules: at most two joints per vertex, and those two have to be a joint and its own parent. The export can correct both for you — the two Fix switches in the export dialog — and says what it changed.

You have two ways to get there:

  • Paint them yourself, in Weight Paint mode, one vertex group per joint. Painted weights are exported exactly as they are.
  • Let the boxes make them. Every joint carries an influence box: a box across the limb that says which vertices it moves. A joint with no painted weights is written the weights its box makes. This is how the game's own models were built.

Working with the boxes

  • In Pose Mode, the selected joint's box carries handles: six grey ones on its faces to resize it, three arrows to slide it, three rings to turn it. Each kind keeps its own distance on screen, so a box a few centimeters across is still easy to hit, and Handles in the 4DS Model tab narrows them to one kind at a time.
  • Fit Influence Box builds one the way the game's own sit: on the joint, aimed at the joint below it, reaching a fifth of the way there, and as wide as the mesh around it.
  • Make Weights From Boxes paints what the export would have made, so you can see it and change it. Pressing it changes nothing about what gets written.
  • Clear All Weights empties the groups again and leaves their order alone, so the joints keep their numbering.
  • The sidebar hides or shows every box at once, draws them In Front of the mesh, and scales the joint markers with Joint Size — all viewport switches, none of which change what is written.

The limits

  • 64 joints below a skinned mesh. The game gathers no more, so the export refuses more. The game's own characters use 25 at most.
  • One skinned mesh per armature.
  • A vertex the mesh keeps for itself — not following any joint — holds its share in the vertex group the Armature modifier holds back, with Invert on.

09Animation

An animation is a .5ds beside the model, keyed by frame name: whatever the model has that the animation names, it moves. The whole of it lives in the 5DS Animation sidebar tab.

Making one

  1. New Animation starts an action on the selected objects.
  2. Put the scene on the game's own rate: the tab's 25 fps button, one frame every 40 ms. This is not optional. An animation numbers its keys in frames and holds no rate of its own, so the game plays every one of them at 25 and nothing in the file can say otherwise — a scene on any other rate is refused, because its keys would land somewhere else in time and the animation would play at a different speed in game than it does here. Pressing the button leaves the keys on the frames they are on, so what you see after it is what plays.
  3. Pose and key as you would anything in Blender. Fit Scene Range pulls the scene's start and end onto what is actually keyed.
  4. File › Export › 5DS Mafia Animation, or tick Write Its Animation when exporting the model and it is written beside it under the same name. Tick Write Its Track as well — on by default — and the .tck holding the travel goes beside it too.
Twenty-five frames a second, and nothing else

An animation numbers its keys in frames and carries no rate of its own: the game spaces them 40 ms apart and there is nowhere in the file to say otherwise. Measured rather than assumed — a .tck states its length in milliseconds and covers the same animation as the .5ds beside it, and in 272 of the game’s 283 pairs the two come to exactly 40 ms a frame. So a scene keyed at 24 or 30 means one thing in Blender and another in game, and the export refuses it rather than write an animation that runs at the wrong speed. The 25 fps button is the one-press fix, and it leaves your keys on the frames they are on.

What the export will tell you

  • Eased keys. The game walks straight from one key to the next, and the format keeps no easing to tell it otherwise, so anything eased plays as a straight line there. The keys are written on the frames you put them on — nothing is resampled — and the report says how many are eased. Set them to Linear to see in Blender what the game will play.
  • Long turns. A rotation of more than half a circle between two keys plays the short way round in game. Fix Long Rotation Turns splits them.
  • The animated object count. A model carries a number saying how many of its frames an animation drives. It follows what the scene has keyed on its own; pin it if you want a number of your own, and the tab says which it is doing.

Event cues

Cues are what the game listens for while an animation plays — a footstep, a sound, a script hook. They live on a Dummy called notify, which the character preset already builds for you. Select it, stand on the frame you want, and add one from the tab. Named events carry free text the game hands straight to whatever is listening.

The movement track

A .tck beside the animation holds where the actor travels while it plays. In Blender it is an empty marked as the movement track, with the model parented under it: key the empty and the travel is what you keyed. The tab names which empty is carrying it, and the export refuses plainly if the model is not under it — the travel would never reach it.

10Shadows, and the rest of the frames

Everything a model can hold that is not an ordinary mesh. Each is a Frame Type, or a Visual Type under Visual, and the Add menu builds every one of them ready to edit.

Shadows (.6ds)

A shadow file is the coarse mesh the engine casts shadows from, one piece per frame of the model, and it carries geometry and nothing else — no materials, no UVs. Mark a mesh with Use As Shadow Piece in its object panel and export File › Export › 6DS Mafia Shadow. It is a separate file that lives beside the model, not something inside it.

Sectors and portals

A sector is a room: a closed mesh with its normals facing inward, which the engine tests points against. A portal is the opening between two of them — a flat outline of at most eight corners, parented to its sector and named after it with _portal1. Both are built by the Add menu, and the check has plenty to say about them if they are not closed.

The others, in a line each

FrameWhat it is
DummyA named box: a mount point, a spawn marker, a script anchor. The box is stored, so resizing the empty changes what is written.
TargetAn empty holding links to other frames by name, bones included. A link to something that is not being exported is dropped with a warning.
OccluderA closed volume that hides what is behind it.
LightThe game's own light, with two-value falloff and a pair of cone angles that Blender's lights cannot hold, so it is its own thing. It shines along local +Y and is drawn with its cone, its range and an aim ball.
BillboardA quad that turns to face the camera — freely, or around one axis. The Add menu builds the upright kind, which is what most of the game's do.
MirrorA surface that reflects, with an authored bound and a view box saying what it is allowed to reflect. Fit View Box sizes it.
Lens flareA stack of sprites drawn along a line from a light. Each element needs a material.
ProjectorA volume that paints a material onto whatever is inside it — a headlight, a lamp on a wall. It projects along local +Y, and the viewport paints it where the game would: see below.

What a projector paints

A projector carries no mesh. It is a volume and a material, and the game works out as it draws which surfaces fall inside that volume, maps the material’s texture across it and paints them. Blender has nothing of the kind — its lights cannot paint a decal, and a texture only reaches a surface through that surface’s own material — so the add-on draws it: the surfaces inside the volume, painted with the texture the way the frame’s transform maps it, stopping at the first thing in the way, as a projector does.

Everything the mode decides is drawn with it:

  • The volume. Two units across and one along the projection axis, carried by the frame’s own transform — so its scale is how big the projection is. Straight On gives a box the same width all the way through; off gives the pyramid inscribed in that box, spreading from the frame’s own point.
  • Depth Falloff. Constant is full strength throughout. Linear is full at the near face and gone at the far one. Triangular is nothing at either face and full at mid-depth — so a surface sitting exactly at the far face of a linear projector takes no paint at all, which is worth knowing before you conclude it is broken.
  • Blend Mode. Additive adds to the surface in game, so black parts of the texture add nothing and only light is left. Alpha Blend draws over it, hiding what is underneath where the texture is opaque — which is what a tyre track or a scratch wants.
  • What the viewport can and cannot show. Blender composites an overlay over the scene rather than adding into it, so an additive projector cannot brighten the surface it lands on. It is drawn with its brightness carried in its opacity instead: black shows nothing, the brightest paint shows fully, and the falloff fades it away. The shape, the texture, the falloff and where it stops are exact; only the brightening is not, which shows on a light surface more than a dark one. Alpha Blend is exact.
  • The color key, where the material carries one, cuts its own color out of the paint as it does anywhere else.

A projector whose material writes no diffuse texture paints nothing, and the panel says so: the texture is the only thing it draws. Turn the whole thing off with Project Textures in the 4DS Model tab — it is drawing only, and changes nothing that is written.

Morphs, in short

A morph is organised into groups, each holding an ordered list of targets that are shape keys. The first target in a group is its basis, and everything in the group is written against it. The + makes a new shape key and adds it; the button below the pair takes one the mesh already carries; the − removes the target and its shape key, unless another group still holds it.

Which vertices a group covers is not something you set: a group that came out of a file keeps the region the file listed for it, and a group made in Blender covers the vertices its own targets move. The panel says which of the two it is.

The command line

The add-on can be driven from a command prompt by the MBT CLI — mbt.bat, beside the add-on's own code. It finds Blender itself and needs nothing else installed:

mbt --install --textures "D:\Hry\Mafia Editovani\maps"
mbt --open "D:\models\tommy.4ds" --check
mbt --open "D:\models\tommy.4ds" --export "D:\out\tommy.4ds"
mbt --open "D:\models\tommy.4ds" --gui

--open takes any of the four kinds and reads which from the name; repeat it to load an animation onto its model. --export writes the scene back out, --save keeps it as a .blend, --check runs the export checks without writing, and --gui leaves Blender open with the result. The exit code is 0 when everything asked for was done, 1 when a step was refused and 2 when the command made no sense — so another program can drive it and know what happened. mbt --help lists the lot.

When something is wrong

  1. Press Check 4DS Scene and read what it says — most refusals carry a suggested fix.
  2. Open the system console for the full report.
  3. Import a model the game ships that does the thing you are trying to do, and look at how it is built. That is the reference that is always right.

Written against Mafia Toolkit 1.0.2, on Blender 5.2. Behavior checked against what the game actually does, and tested against every model shipped with Mafia.
